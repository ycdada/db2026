# 火焰图输出

本文档记录本项目当前已生成的 RMDB 火焰图结果、生成方式和初步热点观察。

## 输出文件

- SVG 火焰图：`profiling/rmdb_flamegraph.svg`
- gprof 文本报告：`profiling/rmdb_gprof.txt`
- folded 数据：`profiling/rmdb_flamegraph.folded`
- 原始 gmon 数据：`profiling/rmdb_gmon.out`
- 生成脚本：`profiling/generate_flamegraph.py`

## 生成环境与方法

当前环境未发现 `perf`、FlameGraph 官方脚本或 PDF/图形 profiling 工具，因此本次火焰图基于 `gprof` flat samples 生成。

使用了独立 profiling 构建目录 `build-profile/`，构建参数包含：

```bash
cmake -S . -B build-profile \
  -DCMAKE_CXX_FLAGS="-Wall -O0 -g -ggdb3 -pg -fno-omit-frame-pointer" \
  -DCMAKE_EXE_LINKER_FLAGS="-pg"
cmake --build build-profile -j
```

生成命令：

```bash
python3 profiling/generate_flamegraph.py --iterations 250
```

脚本会启动 `build-profile/bin/rmdb`，创建临时 profiling 数据库，建 TPCC 小表，加载 `src/test/performance_test/table_data/` 中的小规模 CSV，然后循环执行 250 轮 NewOrder/Payment 风格 SQL workload，最后输出 SVG、folded、gprof 和 gmon 文件。

## 当前热点摘要

`profiling/rmdb_gprof.txt` 顶部 flat profile 显示：

```text
15.83%  Page::Page()
 2.50%  yyparse()
 2.50%  std::_Sp_counted_base<(__gnu_cxx::_Lock_policy)2>::_M_release()
 1.67%  yylex(ast::SemValue*, YYLTYPE*)
 1.67%  ast::SemValue::SemValue()
 1.67%  ast::SemValue::~SemValue()
 1.67%  std::__shared_count<(__gnu_cxx::_Lock_policy)2>::~__shared_count()
 1.25%  std::shared_ptr<ast::Expr>::~shared_ptr()
 0.83%  RmFileHandle::snapshot_rids() const
```

初步观察：

- `Page::Page()` 占比最高，当前 workload 下页面对象初始化或构造路径值得优先确认是否存在重复初始化、批量分配或构造开销。
- parser/lexer 和 AST `shared_ptr`/`SemValue` 构造析构占比较明显，短事务高频 SQL 场景下解析分配开销可见。
- `RmFileHandle::snapshot_rids()` 出现在热点中，说明内存记录快照扫描路径仍有优化空间，尤其是短查询重复扫描时的快照构造成本。

## 注意事项

- 这版不是 `perf` 调用栈采样火焰图，而是 `gprof` flat profile 转换出的 SVG，可用于粗粒度定位热点，但不适合精确判断完整调用链归因。
- `build-profile/` 和 `profiling/` 是本地生成产物，目前未纳入正式源码结构；如需保留，可后续决定是否加入 `.gitignore` 或提交脚本/文档。
- 若后续环境允许 `perf`，建议再用真实调用栈采样生成一版标准 FlameGraph，并与本次结果交叉对比。
